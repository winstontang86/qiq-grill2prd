# 仓库现状扫描清单（Phase 1 用）

在进入拷问前，**自动**扫描仓库以下内容，**不要为这些事情打扰用户**。

## 必须扫描

- 根目录 `README.md`、`CLAUDE.md`、`AGENTS.md` —— 项目大方向、协作约定
- `CONTEXT.md` / `CONTEXT-MAP.md` —— 领域术语字典（**关键**，整份 PRD 必须用这里的规范名词）
- `docs/adr/`、子目录下的 `docs/adr/` —— 已记录的架构决策
- `package.json` / `go.mod` / `pyproject.toml` / `Cargo.toml` 等 —— 技术栈与依赖
- 主目录结构（`src/`、`internal/`、`pkg/`、`app/` 等）—— 已有模块和领域概念

## 按需扫描

- 与本次需求强相关的代码区域（按用户输入里的领域名词搜索）
- 已有 PRD / RFC / design doc 目录（如 `docs/prd/`、`docs/rfc/`）
- 已有的测试目录与命名风格 —— 后续"测试决策"小节要参考

## 输出"仓库认知摘要"（必须）

扫描完成后，用 3-6 行向用户简要确认你对项目和需求的理解，例如：

> 我看到这是一个 XX 项目，使用 YY 技术栈，已有 AA、BB 模块。`CONTEXT.md` 里关键术语包括 P、Q、R。你这次想加的是 CC 功能，它会和已有的 AA 模块产生关联。开始拷问前请确认我的理解对吗？

等用户确认（或纠正）后再进入 Phase 2。

## 收集到的事实如何用

- 用户的描述与代码现状冲突 → Phase 2 中"代码现状交叉验证"环节立刻指出
- 用户用的某个名词不在 `CONTEXT.md` 里 → 加入"待澄清术语"清单，到 Phase 2「领域术语」branch 时挑战
- 用户提的某个能力代码里已经有 → 立刻反问"是否真的要新做，还是复用/扩展现有实现"
